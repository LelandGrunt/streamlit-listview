# Frontend (`streamlit_listview/frontend/`)

These rules extend the root `CLAUDE.md`. The comments next to the code give the measurements behind them.

## Files (`src/`)

- `index.tsx`: the V2 `FrontendRenderer` entry. It mounts one React root per instance into the `.listview-root` scaffold that the Python `html=` defines, and passes `inSidebar` (see *The sidebar swaps two tokens* in `.claude/rules/frontend-theming.md`).
- `Listview.tsx`: the container component. It composes the hooks and the presentational components, and it keeps the handlers that tie them together: `onBodyClick`, `onItemClick` (a stable identity through a ref, so the memoized rows bail out), `onHeaderClick`, and `onSelect`, `onEscape` and `onSlash` for the keyboard.
- `types.ts`: the wire format: `ListviewData`, the shape of the Python `data` dict, and `Id`, the one id type. `__tests__/types.test.ts` pins its keys and types.
- `components/`: the frame, `ListviewHeader` (the pinned search field and the select-all toggle), `ListviewBody` (the scroll frame, the in-flow search field and the listbox or tree) and `ListBlocks` (the placeholder or one `GroupBlock` per block; `GroupBlock` renders a block's ARIA role, its header, its `div.listview-group-rows`, its chunks and its rows); and the parts, `WidgetLabel`, `GroupHeader`, `ListItem`, `SearchField`, `SelectAllToggle`, `NewOptionInput`, `HelpTooltip`, `Markdown`.
- `hooks/`: `useSelection` (the committed selection), `useNewOptionRows` (the `accept_new_options` rows and `allItems`, every row the list renders), `useAddNewOption` (the add field's handler, which also scrolls the added row into view), `useFilter`, `useGroupCollapse` (the groups the options name and `asTree`, wired to `useCollapse`), `useCollapse`, `useRenderBlocks` (the blocks, their chunks, `aria-posinset` and the keyboard's nodes), `useSelectAll` (the toggle's scope, label and state), `useKeyboardNav` (the arrow keys over rows and, in a tree, group headers), `useScrollToId` (the DOM scroll to a row, and `useScrollToGroup` to a header), `useLatestRequest` (the counter that lets only the latest scroll request scroll), `useScrollToItem`, `useColorScheme`, `useRowHeight` (the measured row height behind a skipped chunk's size estimate), `useResetChunkHeights` (makes a skipped chunk whose rows changed forget its remembered height) and `usePopoverPlacement` (the side the help popover opens on, its height cap and its sideways shift; see *The help popover*).
- `utils/`: the shared helpers without hooks (see *One helper per question*).
- `markdown/`: `streamlitPlugins.ts` (the remark plugins), `links.tsx` (the link renderer and `transformUri`) and `detect.ts` (emoji detection). `components/Markdown.tsx` assembles them into a `react-markdown` stack that matches Streamlit's renderer: GFM; remark-directive for `:red[…]`, colors and badges; a preprocess that turns `:material/icon:` and `:streamlit:` into placeholders before parsing; and emoji, imported statically and enabled on demand. Raw HTML stays escaped (no `unsafe_allow_html`). LaTeX renders as literal text, because KaTeX would add about 1.4 MB of inlined fonts to the bundle.
- `bench/`: the frontend-tier benchmark (see `BENCHMARKS.md`). `fixtures.ts` mirrors `demo/data.py::make_large_dataset` and `e2e/perf/cells.py::shape_rows`, and tests in both languages pin the three to the same literals. `*.bench.tsx` runs under `vitest bench` only: the coverage run and the production typecheck skip it, and `npm test`'s `tsc -p tsconfig.test.json` compiles it. `fixtures.ts` falls under both, so it needs full coverage.
- `test/`: the test support: `makeData.ts` (the one `ListviewData` factory, which `bench/fixtures.ts` uses too), `hast.ts` and `setup.ts`.

## One helper per question

**Look in `utils/` before writing a second fold, a second stripper, a second `String(id)` or a second container probe.** Two copies drift apart.

- `ids.ts`: `idKey`, the single `String(id)` row identity that every comparison goes through; `optionDomId` and `groupDomId`, the DOM ids of a row and of a group's treeitem (`aria-activedescendant`, the scroll lookup); `itemIdByKey`; `disabledIdSet`; `sameIds`, the by-value comparison of two id lists; and `parseNewIntId`, the copy of `_options._parse_new_int_id`. With int options a new entry must pass it and is added as a number.
- `blocks.ts`: `blockKeyOf`, the block a row renders in, and `blocksFor`, the blocks of a row list in render order (see *Groups*).
- `text.ts`: `foldForMatch`, the one case and ß fold, shared by the search filter and the `accept_new_options` lookup, so that what the user can find agrees with what they can add. `plainTextLabel`, the one Markdown-to-plain-text stripper, shared by the listbox's accessible name and the help trigger's "Help for &lt;label&gt;". It strips only what the renderer claims: the directives in `BRACKETED_DIRECTIVES` and the `MATERIAL_ICON_TOKEN` and `STREAMLIT_LOGO_TOKEN` patterns, all from `markdown/streamlitPlugins.ts`, and the emoji shortcodes that `node-emoji` knows. A name stripped here but rendered literally there would announce text the user cannot see. What renders verbatim keeps its text: a code span's content, a backslash-escaped punctuation character, a backtick run that closes no code span (`LITERAL_SOURCE`), and a `*`, `_` or `~` run with whitespace on both sides; otherwise a code label such as `` `*` `` loses its accessible name.
- `container.ts`: `isInSidebar`, the one probe for the Streamlit container this instance mounted into.
- `chunks.ts`: `isSkipped` (does the browser skip this render chunk), `forgetHeights` (the one forget cycle, see *Render chunks*), and the `CHUNK_SELECTOR` and `FORGET_CLASS` names.
- `items.ts`: `reuseUnchangedItems` and `runsByKey` (splits a block into its chunks). Every rerun that changes the listview's payload ships the options as freshly parsed JSON: a parameter change, the first rerun after a keyed listview mounts (its persisted selection appears), and each click on a keyed listview. A rerun that changes nothing sends Streamlit's cache reference instead, for a payload of 10 KB or more (`global.minCachedMessageSize`). Without the reuse, each such rerun recomputes every memo keyed on the items and re-renders every row. **Read the options through `Listview`'s `items`, never through `data.items`.**
- `arrays.ts`: `elementAt`, the one checked index access. `noUncheckedIndexedAccess` types `array[i]` as possibly undefined; where the code keeps the index inside the array, call `elementAt`. oxlint forbids a `!` in production code.

## Selection state

The root `CLAUDE.md` states the rules; this section gives the details.

- **`useSelection` seeds from `data.state_selection` because a container move remounts the frontend.** A keyed element id ignores the container, so moving a widget between `st.sidebar` and the main body remounts the frontend while the Python-side state survives; a remount seeded from `default` showed rows that disagreed with the value `listview()` returned. The wrapper ships the field for keyed instances only (`_persisted_selection`: best effort, `None` outside a runtime or when malformed). `default_ids` is the `default` that Python resolved; the value `listview()` returns before the first commit is the V2 mount state `default={"selection": [...]}`.
- **The hook reads both fields at mount only.** Echoing a later `default` into the display would show a selection that `listview()` does not return. A later `default_ids` that differs by value still scrolls to its first id and opens its block (`useScrollToItem`).
- **`reconcileSelection` runs during render.** It drops ids no longer in `items` (unless `accept_new_options` is on), collapses duplicate row keys, canonicalizes an id that spells a row differently (`"7"` becomes the option's int `7`), and truncates past `max_selections`, or past one in single mode. It commits only a result that differs.
- **A container move keeps the selection but resets the UI state.** The remount seeds the selection from `state_selection`; collapse, search and scroll have no persistence channel. The seed also rebuilds the added entries, so an added entry survives the move only while it is selected.
- **`useCollapse` seeds each group from `collapsed_groups` the first time it sees that group.** A group counts as seen only while `collapsible_groups=True` (its header is a toggle), so turning the feature on later still seeds groups first shown while it was off. For groups present at mount, a later change of `collapsed_groups` does nothing on a keyed instance.

## Groups

- **The block without a group renders last, in every `sort` mode.** `blocksFor` in `utils/blocks.ts` builds it after the named groups, and both the rendered rows and `aria-posinset` come from that one function (`useRenderBlocks`). In a grouped list the block carries the `ungrouped_label` header; in a list without groups it has none.
- **A group named like `ungrouped_label` joins that block** (`blockKeyOf`), so no two headers read the same. `_options.sort_items` sorts the two as one block.
- **`useCollapse` keys that block as `null`.** No group name can collide with it. `useGroupCollapse` maps `ungrouped_label` in `collapsed_groups` to `null`, so a list that names the header collapses the block.
- **`expand()` counts as a sighting.** An add opens the block without a group in the event that creates it; without the sighting, the `"all"` seed would close the block on the next render and hide the new row.
- **A block renders collapsed only while it has a header.** `useCollapse` drops a stale key in an effect, after the render, so a list that a rerun left without groups would otherwise show an empty frame for one render.
- **`ListBlocks` keys each block by `groupDomId`, never by its position or its raw name.** Under a positional key, a search that hid an earlier block handed every later block the previous block's element, and React rebuilt all of their rows, the survivors included. A raw name cannot key the block without a group, and a plain string sentinel for it (`"__ungrouped__"`) collided with a group of that name. `groupDomId` prefixes every named group, so the two kinds cannot share a key.

### Collapsible groups make a tree

- **With `collapsible_groups` and at least one group, the list is a WAI-ARIA tree** (`asTree` in `useGroupCollapse`, `blockAria` in `components/GroupBlock.tsx`). A listbox may own only options and groups of options, so a toggle inside it fails axe-core's `aria-required-children`, and no role of a listbox carries `aria-expanded`; the tree is the pattern that opens and closes. A list without groups, or with groups that do not collapse, stays a listbox.
- **The markup:** the listbox element takes `role="tree"` and keeps the class `listview-listbox`, which the stylesheet and the tests use in both roles. Each block is a `treeitem` (`aria-label`, `aria-expanded`, `aria-level` 1, its place among the unfiltered blocks, the id `groupDomId`). Its rows sit in `div.listview-group-rows` with `role="group"`, as `treeitem`s at `aria-level` 2 whose `aria-posinset` and `aria-setsize` count their block. In a listbox the same wrapper carries `role="none"`, and the block itself is the named `role="group"`.
- **`aria-expanded` follows the group's own state,** as the chevron and the arrow keys do, also while a search shows the rows of a closed group: clearing the search hides the rows again. This is a design decision, not a WAI-ARIA requirement. A screen reader announces such a group as collapsed while its matching rows stay reachable. Change it only together with the chevron, the arrow keys and the test "reports a closed group as closed while a search shows its rows" in `Listview.test.tsx`.
- **The header is an `aria-hidden` div in both modes, never a `<button>`.** The treeitem carries the name; a focusable header inside the tree would fail the same rule. The keyboard reaches the header as a `GroupNode` in `useKeyboardNav`: ↑/↓/Home/End stop on it, → opens a closed group or steps into an open one, ← closes an open group or steps from a row to its header, and Enter/Space toggle it. A click on the header toggles the group and moves the active descendant to it (`onHeaderClick`). The list is one Tab stop.
- **`scrollToGroup` (`useScrollToGroup`) brings a header into view.** The header is sticky, so it scrolls only for a group wholly outside the frame, measured from the group's block.

## Render chunks

**Rows render in keyed chunks of at most 100 (`ROW_CHUNK_SIZE` in `hooks/useRenderBlocks.ts`, unrelated to the bundle's single chunk), and the browser skips the chunks it does not show.** Each chunk is a `div.listview-chunk` with `role="none"` inside its block's `div.listview-group-rows`, its rows are its children (`components/GroupBlock.tsx`), and `useRenderBlocks` splits each block into chunks (`runsByKey`). Two costs set this shape:

- **React:** one update that brings thousands of new rows into a single parent (clearing the search, expanding a big group, a rerun that adds options) costs O(k²), because React's `getHostSibling` searches forward through every following new sibling once per row.
- **The browser:** `listview.css` gives each chunk `content-visibility: auto`, so a chunk outside the scrollport skips style, layout and paint (`BENCHMARKS.md`, *Off-screen render chunks*).

The rules:

- **A row's chunk number is its index in `allItems` (the options and the added entries) divided by 100 (`chunkOf`),** never a value derived from the filtered rows. A filter then cannot move a row into another chunk, so narrowing keeps every survivor's DOM node. Blocks reorder the rows, so one chunk number can appear in several blocks, each time as a chunk of its own.
- **A skipped chunk's height is an estimate:** `--listview-chunk-rows` (the chunk's own row count, set inline) times `--listview-row-height` (the first rendered row's height). `useRowHeight` publishes the height on the listbox, which React gives no `style`. Never publish it on an element that React styles.
- **A skipped chunk keeps the height it last rendered at.** `content-visibility: auto` implies `contain-intrinsic-size: auto`, so the browser ignores a new estimate, and a forced layout of the chunk's rows changes nothing. `forgetHeights` therefore gives such a chunk `.listview-chunk--forget` (`content-visibility: hidden`, which implies no `auto`) for two animation frames, and the browser drops the remembered height without rendering the chunk. `useResetChunkHeights` runs it for the chunks whose row count changed. `useRowHeight` runs it one frame after a changed height is laid out, for the skipped chunks whose box disagrees with the estimate and only for those: hiding a chunk of the right height blanks it for a frame. Never write `auto` into the chunk rule's `contain-intrinsic-block-size`, or the forget rule cannot drop it.
- **Read chunk boxes in a later frame than a forced layout of their rows.** A probe that reads them in the same task sees the real heights and misses a stale one.
- **`useRowHeight`'s ResizeObserver watches the listbox, never a row.** The browser lays out no row inside a skipped chunk, so an observer on a row reports nothing while the list is scrolled away from its top. The listbox resizes whenever the rows do. The hook measures the first row in the next animation frame, not in the observer's callback: a write there resizes the listbox inside the same delivery loop, which Chromium reports as "ResizeObserver loop completed with undelivered notifications". A commit that keeps its first row measures nothing, so this hook forces no layout on a keystroke or a click. `scrollToId` measures on every arrow key (below).
- **`scrollToId` waits and measures for itself.** After a key-change remount, the new shadow root loads the stylesheet frames after the first commit, so `scrollToId` first waits, a frame at a time and 600 at most, until the body is a scroll container; a `scrollTop` written earlier is lost. It then waits, four frames at most, while the target row's chunk carries the forget class, because a row in a hidden chunk has no geometry. Right before it measures the target, it measures the first row again through the function `useRowHeight` returns, because the first measurement after a remount can be of an unstyled row. `getBoundingClientRect` lays out a row inside a skipped chunk on request.
- **Only the latest scroll request scrolls.** The waits let a later request overtake an earlier one, which then moved the list away from the focused row. `useScrollToId` and `useScrollToGroup` start each request through one `useLatestRequest` counter (`beginScroll` in `Listview`), and a request that is no longer the latest stops. A new scroll path starts its requests through the same counter.
- **`scrollToId`'s sticky-header check finds the group with `closest(".listview-group")`,** because a row's parent is its chunk.
- **Accessibility:** Chromium's accessibility tree holds only the rendered chunks' options. Each row therefore reports `aria-posinset`, its one-based place in the unfiltered render order (`rowPosition` in `useRenderBlocks`, built by the same `blocksFor` as the rendered blocks), and `aria-setsize` (`listSize`, the number of places handed out: every row). In a tree both count the row's block instead. Both depend on the items only, so a keystroke or a click changes neither. A row still re-renders when its `selected`, `focused` or `muted` prop changes: a click re-renders the rows whose selection changed, an arrow key the rows that lose and gain the focus, and reaching or leaving `max_selections` every unselected row. Adding an option re-renders every row once, because `aria-setsize` changes (in a tree, only the rows of the block it joins). Firefox, Safari, real screen readers and find-in-page are untested.
- **Chromium rounds row positions per chunk,** so with fractional row heights a row can sit one device pixel off its former place, and a GIF can change that way.
- **Never** flatten the chunks back into one `map`, derive a row's chunk from the filtered rows, or drop `role="none"`.
- **Browser tests:** `e2e/test_performance.py` covers the forget cycle after a search, `e2e/test_jump_remount.py` the scroll after a remount, and `e2e/test_row_height.py` a rerun that changes `item_height`, `content_font_size` or `show_grid_lines`.

## Search, the add field and the help

- **A search filters only while its field shows.** A keyed instance keeps `query` across a rerun that turns `enable_search` off; `Listview` filters by `activeQuery`, which is empty then, so no hidden text narrows the rows, the Select all scope or the first Esc. The text stays, and the field brings it back when search returns.
- **The add field refuses what it cannot select, and keeps the text.** `useAddNewOption` returns a hint instead of `null` for a new entry at the cap, for an existing row at the cap that is not selected, and for a disabled row that is not selected (`refusalForRow`); the cap hint is `st.multiselect`'s own message. A typed label that names an existing row still reveals that row, refused or not. A row already selected is taken as it is.
- **An add keeps the search,** by design. A new entry the query does not match stays hidden until the search clears, and there is no row to scroll to.

### The help popover

- **The focus counts for the whole help, the trigger and the popover.** `HelpTooltip` tracks it on its wrapper and closes only when `relatedTarget` lies outside, so Tab moves from the trigger onto a link in the help; the popover follows the trigger in the DOM for that reason. Closing on the trigger's own blur unmounted the popover before the focus arrived, and the focus fell to `<body>`. Esc anywhere in the help focuses the trigger first, then closes.
- **`usePopoverPlacement` keeps the popover inside its bounds:** the viewport, cut down by every ancestor that clips its content (`boundsOf`), because a widget in the sidebar sits in Streamlit's sidebar scroll box. The popover opens above the trigger while the help fits there, else on the side with more room (`data-placement="below"`), and scrolls the rest; the hook's comments say when it measures. The popover is `width: max-content`, because shrink-to-fit sizes it to the help slot, which beside a label that fills the row is as wide as the icon. A popover that scrolls gives its body `tabIndex=0`, so the keyboard can scroll it.
- **The body scrolls, never the popover.** The hover bridge (`::before`) lies outside the popover's box, and overflow on the popover would clip it; the pointer would then lose the popover crossing the gap. The popover has no padding of its own, so the body's box is the popover's.
- **No portal.** The popover stays inside the instance's shadow root, where it inherits the theme's `--st-*` properties. A document-level portal would need the theme passed to it.
- **Browser tests:** `e2e/test_help_popover.py` (keyboard, placement in the main body and the sidebar, the hover bridge below the trigger, a code label's name). The two link tests skip WebKit, which, like Safari by default, leaves links out of the Tab order.

## Markdown safety

- **Nothing renders raw HTML.** No production source uses `dangerouslySetInnerHTML` or react-markdown's `allowDangerousHtml`, and `rehype-raw` and `html-react-parser` are no dependencies. `__tests__/markdown-xss-guard.test.ts` enforces all three.
- **`transformUri` (`markdown/links.tsx`) is the only URL gate.** `Markdown.tsx` passes it as `urlTransform`, which replaces react-markdown's own safelist. It turns `javascript:`, `vbscript:`, `file:`, `blob:` and every `data:` URL except an image's `data:image/` into `#`.
- **The icon preprocess rewrites the whole source, so the restore pass covers every field that holds source text.** `materialIconPreprocess` turns `:material/…:` and `:streamlit:` into Private-Use sentinels before parsing; only text nodes become icons. `createRemarkRestoreIconSentinels` restores the rest in `value` (code), `url`, `title` and `alt`, on the syntax tree, before `transformUri` sees the URL; otherwise a link to `…/:material/check:` points at a percent-encoded sentinel.
- **`isSafeCssColor` (`markdown/streamlitPlugins.ts`) admits a `foreground` or `background` value of `:color[…]{…}` only when it is a single well-formed color.** It drops any other value before the inline `style` is built, so a label cannot inject CSS.

## Theming and painted states

**The rules for the stylesheet live in `.claude/rules/frontend-theming.md`:** the `--st-*` tokens, the sidebar swap, the surface pairs and the painted states that copy native widgets. ## Clicks on the frame

- **`onBodyClick` in `Listview.tsx` forwards a click on the frame's empty space to the listbox** (below the last row of a list shorter than `height`), but only when the target is `.listview-body` itself. Rows and the in-flow search field focus their own target, and forwarding every bubbled click would pull the caret out of an input. It is `onClick`, not `onMousedown`: focus set during mousedown loses to the browser's own mousedown handling unless the default is prevented, and preventing it on the scroll container risks the scrollbar.

## The tests depend on the markup

The GIF scenarios find the widget by these `data-testid`s: `stListview` (the root that the frame, `settle()` and the key badge measure), `stListviewOption-<id>`, `stListviewSearch`, `stListviewSearchClear`, `stListviewSelectAllToggle`, `stListviewGroup` and `stListviewNewOption`; and by the classes `listview-help-trigger` and `listview-body`. The e2e suite uses more test ids, such as `stListviewNewOptionHint` and `listview-widget-label`, and more `listview-*` classes; `e2e/perf/measure.py` finds a collapsible header by `.listview-group-header--collapsible`, which every checkout carries. `stListviewGroup` sits on the header, not on the group's treeitem, which carries the role and `aria-expanded`. Before you rename a test id or a class, search `e2e/` and `scripts/gif/` for it, and fix every use in the same change. After a visible change, run the visual comparison and regenerate the hero GIF (root `CLAUDE.md`, *README GIFs*).
